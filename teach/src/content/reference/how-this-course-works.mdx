# 这份课是怎么写的

<Lede>八条规则。它们不是口号，是踩过坑之后定下来的；每一条都能在这份课里找到对应的痕迹。</Lede>

## 为什么要把规则写出来

因为这些规则大多是你纠正我之后才有的。写在这里，你能知道我按什么标准交付，也能在我违反时直接指出来。

## 一、先量，再写

每一个数字都来自真实运行，不靠推断。写 TTFT 那一节之前，我先用探针打了 5 个尺寸、每个 3 次；写重试那一节之前，先让故障服务器按概率失败跑了 40 次。

如果你看到课里写「大约 44 ms/千 token」，那是拟合出来的；如果写「业界常说」，那是**没有实测**的推断，我会明确标出来。

**分辨方法**：课里出现「我们测到」「实测」，是可以复现的；出现「一般认为」「常见说法」，是没有验证的。

## 二、写代码之前，先给数据形状

这条是你教的。

「429 要带 Retry-After」这句话没用——因为读者不知道 `Retry-After` 在响应头里、返回的是字符串、单位是秒。

所以凡是要求写代码的地方，都会先给出**这一节会碰到的所有数据形状**：字段名、类型、单位、可能为 `null` 或 `undefined` 的情况。位置在三个地方：

- 课里用它的那一段（表格）
- 练习文件顶部（注释块）
- 速查卡（完整版）

## 三、讲到某个响应，就贴真实原文

这条也是你教的，而且我改了两次才理解对。

第一次我只给了字段表，你说「这种不应该让我去速查表里看」；第二次我加了一句「翻速查卡」，你说「应该直接把真实响应放这里」。

所以现在：课里提到 429，就贴完整的 HTTP 响应（含响应头）；提到「取消时收到了什么」，就贴那段**断在 JSON 中间**的原始字节。字段表是索引，原文是证据。

## 四、速查卡是补充，不是替代

判断标准一句话：**把速查卡删掉，这一节还读得懂吗？**

读不懂就是没写清。速查卡只承担「还有更多」的延伸，不承担「这一节需要的基本信息」。

## 五、每节都有能拿在手里的东西

不接受「看完了」作为完成标准。每节末尾都有一句「你的产出」，是一个能跑起来的文件、一张表、或者一段 200 字的说明。

## 六、练习自带自检

每个练习文件末尾都有自检代码，跑 `npm run ex:xxx` 就知道自己对没对，不需要等我批改。

而且**留空的脚手架要能好好说话**：没写的时候提示「还没开始写」，而不是抛一个莫名其妙的 `TypeError`。

## 七、免费优先

能用 mock 的绝不用真 API。故障服务器、mock 服务器都是本地起的，可以无限次跑。

必须打真 API 的（比如 TTFT、token 计数），会把成本写清楚，通常几分钱到两毛钱。

## 八、错了就说是错的

课里出现过这些情况，都写在页面上了：

- 同一段 TTFT 数据，两次会话的斜率差一倍（24.1 vs 44.4 ms/千token）——两个都列出来，并说明「系数不能跨会话借用」。
- `temperature = 0` 时三次回答不一样——如实写成「观察」，并注明「只跑了一轮，原因没验证」。
- 一本书某章讲的是「预算实现」，不是我先前说的「成本拆解」——改了说法。

<Callout kind="do" title="怎么用这几条">

如果你读某一节时卡住了，先问自己：是概念不懂，还是不知道数据长什么样？

- 概念不懂 → 告诉我哪一段，我补解释或换类比。
- 不知道数据长什么样 → 这是**我的问题**，直接说「你把字段贴出来」，我就该在那一段补表。

</Callout>

## 课程的结构

```
第 0 章  把机器接上        —— 原生 API 的四个动作
第 1 章  推理的成本结构    —— prefill/decode、KV cache、TTFT
第 2 章  能扛的客户端      —— 超时、重试、取消
第 3 章  Agent 的本质与循环 —— 你现在在这里
…
```

每一章 = 若干节课 + 至少一个练习。每节课大约 30–45 分钟，一章大约 2–4 小时。

站点只记进度在本机，不上传任何地方。右侧目录、侧栏打勾都是在浏览器本地存的。
