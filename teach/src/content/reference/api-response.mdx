# Chat Completions：原始请求与原始响应

<Lede>这一页放的是真实的请求和响应——你在课程里发出去的，和服务器原样回给你的。忘了字段在哪，先看原始形式，再看下面的字段表。</Lede>

## ① 最小的一次请求（非流式）

### 原始请求

```bash
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -d '{
    "model": "deepseek-flash",
    "messages": [{"role": "user", "content": "只回答：一二三四五"}],
    "thinking": {"type": "disabled"},
    "max_tokens": 16
  }'
```

三件事缺一不可：`Content-Type`、`Authorization`、一个合法的 `model`。`thinking` 不写就是开启状态，会多花钱。

### 原始响应（实测，一个字都没改）

```json
{
  "id": "bcea791b-eff5-40fb-9d0e-8aebbd692230",
  "object": "chat.completion",
  "created": 1794471748,
  "model": "deepseek-flash",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "一二三四五"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 3,
    "total_tokens": 13,
    "prompt_tokens_details": {
      "cached_tokens": 0
    },
    "prompt_cache_hit_tokens": 0,
    "prompt_cache_miss_tokens": 10
  },
  "system_fingerprint": "bc19ba97cbe016479903222bb1578db6"
}
```

怎么读：**答案在 `choices[0].message.content`**，为什么结束看 `choices[0].finish_reason`，花了多少看 `usage`。

## ② 同一个请求，改成流式

只多两个参数：`stream: true`，和 `stream_options.include_usage: true`（不加它就没有 `usage`）。

### 原始请求

```bash
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -d '{
    "model": "deepseek-flash",
    "messages": [{"role": "user", "content": "只回答：一二三四五"}],
    "thinking": {"type": "disabled"},
    "stream": true,
    "stream_options": {"include_usage": true},
    "max_tokens": 16
  }'
```

`curl` 要加 `-N`（关掉 curl 自己的缓冲），否则你会以为它一次性吐出了全部——那其实是 curl 在攒。

### 原始响应（SSE 字节，共 6 个事件 + `[DONE]`）

第一个事件（把 JSON 展开显示，**线上是单行**，换行只是为了能读）：

```text
data: {
  "id": "f7b63502-7a0f-46f2-92dd-65b9957fd9c5",
  "object": "chat.completion.chunk",
  "created": 1794471749,
  "model": "deepseek-flash",
  "system_fingerprint": "bc19ba97cbe016479903222bb1578db6",
  "choices": [
    {
      "index": 0,
      "delta": {
        "role": "assistant",
        "content": ""
      },
      "logprobs": null,
      "finish_reason": null
    }
  ],
  "usage": null
}
```

最后一块：`delta` 是空的，真正有用的是 `finish_reason` 和 `usage`：

```text
data: {
  "id": "f7b63502-7a0f-46f2-92dd-65b9957fd9c5",
  "object": "chat.completion.chunk",
  "created": 1794471749,
  "model": "deepseek-flash",
  "system_fingerprint": "bc19ba97cbe016479903222bb1578db6",
  "choices": [
    {
      "index": 0,
      "delta": {
        "role": "assistant",
        "content": ""
      },
      "logprobs": null,
      "finish_reason": null
    }
  ],
  "usage": null
}
```

流结束的标记：

```text
data: [DONE]
```

中间还有 3 个内容块，结构和第一个完全相同，只是 `content` 依次是「二」「三」「四」。

三个必须注意的地方：

- 每个事件是 `data: ` 加一行 JSON，**事件之间是一个空行**（所以按 `\n\n` 切）。
- 最后一块 `delta` 是空的，真正的收尾信息是 `finish_reason` 和 `usage`。
- `data: [DONE]` 不是 JSON，解析前要先跳过。

## ③ 工具调用

### 原始请求（多一个 `tools`）

```bash
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -d '{
    "model": "deepseek-flash",
    "messages": [{"role": "user", "content": "北京天气怎么样？"}],
    "thinking": {"type": "disabled"},
    "tools": [
      {
        "type": "function",
        "function": {
          "name": "get_weather",
          "description": "查询指定城市的天气",
          "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string", "description": "城市名"}},
            "required": ["city"]
          }
        }
      }
    ]
  }'
```

### 原始响应（实测）

```json

  "id": "f927e795-81ff-4f9c-a31e-031b7dcccef1",
  "object": "chat.completion",
  "created": 1794471750,
  "model": "deepseek-flash",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "",
        "tool_calls": [
          {
            "index": 0,
            "id": "call_00_PXgQkd80LET4I6O91WQG1216",
            "type": "function",
            "function": {
              "name": "get_weather",
              "arguments": "{\"city\": \"北京\"}"
            }
          }
        ]
      },
      "logprobs": null,
      "finish_reason": "tool_calls"
    }
  ],
  "usage": {
    "prompt_tokens": 274,
    "completion_tokens": 38,
    "total_tokens": 312,

      "cached_tokens": 0
```

两个关键点：`finish_reason` 变成 **`tool_calls`**，说明这轮不是回答而是「请求调用」；`function.arguments` 是**字符串**（`"{\"city\": \"北京\"}"`），不是对象，要 `JSON.parse` 之后才能用。

## ④ 出错的原始响应

把模型名写错，看服务端真实返回：

```bash
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -d '{"model": "no-such-model", "messages": [{"role": "user", "content": "hi"}]}'
```

```json
{"error":{"message":"The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed no-such-model. (request_id: 696af41b-5019-41c8-bba6-ace220b1f01f)","type":"invalid_request_error","param":null,"code":"invalid_request_error"}}
```

**错误响应和成功响应长得完全不一样**：没有 `choices`，只有一个 `error` 对象；HTTP 状态码是 400，而 `fetch` 不会因为这个状态码抛错——所以你必须自己检查 `res.ok`。

## 响应顶层

| 字段 | 含义 |
| --- | --- |
| `id` | 本次请求的唯一 id。报障时给服务端看这个。 |
| `object` | `chat.completion`（非流式）/ `chat.completion.chunk`（流式） |
| `created` | Unix 秒 |
| `model` | 实际服务的模型，可能和你请求的不同 |
| `choices` | 应答数组，**通常只有 1 个** —— 你几乎总是取 `[0]` |
| `usage` | token 统计。**流式下必须显式要才有** |
| `system_fingerprint` | 服务端配置指纹。变了说明后端配置动过 |

## choices[0]

| 字段 | 含义 |
| --- | --- |
| `message.role` | 总是 `assistant` |
| `message.content` | **答案**。调工具时可能是 `null` |
| `message.reasoning_content` | 思考过程。**只在 `thinking` 开启时出现**，要单独渲染 |
| `message.tool_calls` | 模型想调的工具。`function.arguments` 是**字符串**，要 `JSON.parse` |
| `finish_reason` | 这轮为什么结束 |

## finish_reason 全表

| 值 | 含义 | 你的代码该做什么 |
| --- | --- | --- |
| `stop` | 模型正常说完了 | 收工，渲染 content |
| `length` | 撞到 `max_tokens` 上限被截断 | **答案不完整**：加大上限或分段续写，别当成功 |
| `tool_calls` | 模型要求调工具 | 执行工具 → 以 `role:"tool"` 回填 → **再来一轮** |
| `content_filter` | 被内容策略拦截 | **不要重试**，重试还是被拦 |
| `insufficient_system_resource` | 服务端资源不足 | **可以重试**（退避后再试） |
| `aborted` | 被中断 | 检查是不是你自己取消的 |

## usage 字段

```text
prompt_tokens       = prompt_cache_hit_tokens + prompt_cache_miss_tokens   # 恒等式
completion_tokens   # 模型生成的部分（含 reasoning_tokens）
total_tokens        = prompt_tokens + completion_tokens

prompt_tokens_details.cached_tokens          # 与 hit 同义
completion_tokens_details.reasoning_tokens   # 思考消耗；开启 thinking 时才有
```

<Callout kind="warn" title="流式下拿 usage 的坑">

`stream: true` 时**默认不带 usage**。必须显式加：

```json
"stream_options": { "include_usage": true }
```

开了之后**每个 chunk 都带 `usage` 字段**，但只有**最后一个是非 null**。
没有单独的 usage-only chunk —— 统计搭在最后一个内容 chunk 上。

</Callout>

## 已知陷阱（实测）

| 陷阱 | 后果 |
| --- | --- |
| `thinking` 默认**开启** | `temperature` 无效；`max_tokens` 默认 64K；响应多 `reasoning_content` |
| `stream_options.include_usage` 默认不开 | 流式响应**完全拿不到 token 统计** |
| `tool_call_id` 与 `tool_calls[].id` 不匹配 | **HTTP 400**，服务端强制校验。必须原样透传 |
| `role:"tool"` 但前面没有 `tool_calls` | **HTTP 400**：`Messages with role 'tool' must be a response to a preceding message with 'tool_calls'` |

## 成本速算

```text
# 低峰价，$ / 1M token。高峰（北京时间 08:30–00:30）翻倍。
flash:  命中 $0.003   未命中 $0.15   输出 $0.60
v4-pro: 命中 $0.022   未命中 $0.66   输出 $1.98

成本 = hit/1e6 × 命中价 + miss/1e6 × 未命中价 + completion/1e6 × 输出价
```

养成习惯：**每次调用都算一遍量级**。面试会问「一天一百万次要多少钱」。
